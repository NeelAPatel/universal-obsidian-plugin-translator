# UOPT v0.1.5 — resilient Ollama translation protocol

## Goal

Prevent local Ollama models from losing an entire translation batch because one response is malformed JSON, while preserving UOPT's atomic file-write safety and translation quality.

## Provider behavior

OpenAI keeps its JSON-schema Structured Outputs path unchanged.

Ollama stops requesting JSON-schema output. It uses a minimal line protocol:

`candidate-id<TAB>translation`

Use the literal sentinel `__SKIP__` when a candidate is not user-facing and must not be translated. Literal tab/newline/carriage-return/backslash characters inside translations are escaped as `\\t`, `\\n`, `\\r`, and `\\\\`.

The parser accepts valid candidate lines independently. Unknown IDs and malformed lines do not invalidate valid lines. Missing/unresolved candidate IDs are retried in a smaller follow-up request. Ollama gets up to three total protocol attempts for a candidate set.

If candidates remain unresolved, the provider throws a Provider format error carrying all translations already recovered. The service persists those recovered translations as translation memory without writing a partially translated target file. A subsequent Retry file call therefore sends only unresolved candidates.

## Batching

Keep the existing character budget. Generated/bundled source that exposes comments such as `// src/settings.ts` gives candidates a transient semantic/source-section label. UOPT prefers packing on source-module boundaries when that does not increase the number of provider calls. If semantic packing would create more calls than the existing sequential character-budget strategy, UOPT falls back to the baseline batching while retaining the source-section labels in the prompt. Translation quality therefore gains module context without a provider-call cost regression.

## Prompt quality

Ollama receives the same Obsidian glossary and human-facing/machine-facing rules as OpenAI, plus explicit line-protocol instructions. Each candidate includes source section, text, kind, nearby code context, and any prior translation. Translation remains contextual and natural rather than literal.

## Safety

UOPT still writes a target file only after all provider work for that file is complete, JavaScript/JSON validation passes, and the pre-write source hash still matches. Partial provider success is retained only as translation memory until the file can complete safely.

## Diagnostics

Unresolved Ollama protocol output is classified as Provider format. Diagnostics include the batch metadata already introduced in v0.1.4. The exact error includes unresolved candidate IDs/count and the number of recovered translations.

## Testing

Regression tests cover:

- line-protocol parsing with one malformed line among valid translations;
- SKIP decisions;
- code-fence/noise tolerance;
- retrying only unresolved candidates;
- preserving successful translations across a terminal protocol failure;
- service persistence of partial translation memory without modifying the target file;
- semantic batching by `// src/...` module boundaries;
- OpenAI Structured Outputs regression behavior;
- complete build/runtime/package suite.
