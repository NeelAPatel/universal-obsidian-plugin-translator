# UOPT v0.1.4 Diagnostics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Surface exact translation failures with structured context, file-level diagnostics, copy/retry actions, and batch attribution while preserving the existing translation pipeline.

**Architecture:** Extend the existing file state with a serializable `lastFailure` diagnostic object and add small classification helpers. Propagate current batch metadata through translator/service calls, then render those diagnostics in Activity and Plugin Detail. Retry uses the same service translation path with an explicit single-file target override.

**Tech Stack:** CommonJS JavaScript, Obsidian Plugin API, Node test runner, existing UOPT build/package scripts.

## Global Constraints

- Version is `0.1.4`.
- Do not redesign the translation engine.
- Keep `lastError` for backward compatibility.
- Do not log full provider request/response bodies.
- Retry only the selected failed approved file.
- Successful translation clears `lastFailure` and `lastError`.
- Existing snapshot, validation, hash-check, and atomic-write behavior remains the write path.
