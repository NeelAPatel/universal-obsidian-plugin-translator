# UOPT v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local-installable Obsidian desktop plugin that scans installed community plugins for non-English user-facing text, translates approved files through OpenAI or Ollama, preserves recoverable snapshots, and exposes the locked Scan/Translate settings UX.

**Architecture:** UOPT is a desktop-only, manual workflow. A deterministic local scanner fingerprints plugin files, finds foreign-language text candidates, tracks per-plugin/per-file approval state, and prepares a compact plugin context memo. Translation providers receive only candidate text, nearby source context, and plugin context; returned replacements are surgically applied to exact string/document regions, validated, snapshotted, and written back in place. No polling or background automation runs while idle.

**Tech Stack:** Obsidian plugin runtime (CommonJS JavaScript), Node.js built-ins (`fs`, `path`, `crypto`, `vm`), Obsidian `requestUrl` for OpenAI/Ollama/GitHub context, Node built-in test runner.

## Global Constraints

- Product/project name: Universal Obsidian Plugin Translator (UOPT), v0.1 PoC.
- Scope: installed Community Plugins and locally shipped user-facing docs/help; no themes, CSS snippets, core plugins, or runtime network-content interception.
- Scan is read-only and makes no translation-provider request.
- No idle polling, timers, automatic scans, or automatic provider requests.
- New plugin files start blocked; new files added later start blocked; previously translated/approved changed files remain eligible.
- Translate modifies installed files in place only after recoverable snapshots and validation.
- OpenAI and Ollama are the two v0.1 providers. Provider settings persist.
- Main UX: Scan All, Translate All, per-plugin Scan/Translate, per-plugin bulk-disable toggle, selectable summary row, detail/file permissions, Model Settings, Activity.
- Model Settings and Activity render in the left column.
- Plugin and file tables show at most five rows before scrolling, include search, and support sorting on every displayed sortable column.
- Build/package is local only; no GitHub repository or GitHub development workflow is used.
