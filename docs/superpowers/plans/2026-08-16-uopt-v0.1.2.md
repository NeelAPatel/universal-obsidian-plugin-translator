# UOPT v0.1.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship UOPT v0.1.2 with a full-width ordered settings UX, aligned table actions, selectable file preview, localization-aware scanning, canonical project metadata, GitHub CI/release automation, and an easy three-file install artifact.

**Architecture:** Keep the existing bundled CommonJS runtime and local-only scan/provider-on-translate model. Add pure localization-artifact classification to the scanner, a guarded read-only file preview service, and simplify the settings page into one full-width ordered flow. Restructure the repository so root metadata/workflows describe the project and implementation lives under `uopt/`.

**Tech Stack:** Node.js 22 tests/build scripts, CommonJS, Obsidian Plugin API, GitHub Actions.

## Global Constraints

- Release version: 0.1.2.
- Project title: Universal Obsidian Plugin Translator.
- Shorthand: UOPT.
- Plugin ID: uopt.
- Runtime install payload: exactly `main.js`, `manifest.json`, `styles.css` in `.obsidian/plugins/uopt/`.
- Scan remains read-only/local and does not call translation providers.
- New plugin/new file translation requires explicit permission; previously approved changed files remain approved.
- No polling or background translation while idle.
